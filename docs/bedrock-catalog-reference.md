# Bedrock catalog parity

## Reference comparison

The supplied 3:25 Bedrock desktop recording shows horizontal Construction,
Equipment, Items, Nature, and All/search tabs. In particular:

- Construction starts with Planks, Walls, Fences, Fence Gates, and Stairs.
- Equipment groups armor by slot and tools by type, rather than by material.
  Helmets, Chestplates, Leggings, Boots, Swords, Spears, and Axes lead the list.
- Equipment also contains cooked and miscellaneous food. Items includes
  functional blocks, signs, transport, and redstone. These are not equivalent
  to the Java creative inventory's tab assignments.
- Group tooltips use category names such as "Helmets" and "Decorative Stone",
  and the group plus badge is at the bottom-right of a tile.
- Around 1:00 the Helmets group is expanded: its minus-marked header remains,
  followed immediately by the material variants, including leather again as a
  child. This matches the mod's existing header-plus-children arrangement.
- Searching for `pist` filters the list to a Piston result.

The recording does not establish controller key bindings or held-navigation
boundaries. Existing non-crafting group headers, inline expansion, held-navigation
stops, and the user's requested separated expansion outlines are retained.

## Data sources

The bundled offline catalog is generated by `tools/import_bedrock_catalog.py`:

1. [pmmp/BedrockData creative catalog](https://github.com/pmmp/BedrockData/tree/bdb44a48fb6beffb6e9f6864f06d2232eb62b6a3/creative),
   extracted from Bedrock 1.26.30 packet traces. This includes loose entries as
   well as the order of categories, groups, and their members. License: CC0.
2. [GeyserMC Java 26.3 item mappings](https://github.com/GeyserMC/mappings/blob/81700ab543c1f4e9f9041f58dac4154ecb0d0c8b/items.json),
   to translate legacy Bedrock names and data values to Java identifiers.
   License: MIT.
3. [Mojang Bedrock sample English labels](https://github.com/Mojang/bedrock-samples/blob/15701fa9c13923f12662984c32c124327e40e3d3/resource_pack/texts/en_US.lang),
   for group names. The upstream license is bundled with the catalog.

Upstream license texts are included in the JAR under
`bedrock_recipe_book/licenses/`. The importer pins revisions; runtime does not
fetch data from these services.

The [Microsoft catalog documentation](https://learn.microsoft.com/en-us/minecraft/creator/documents/craftingitemcatalogdocumentation)
confirms that the creative inventory and recipe book share a catalog, with the
recipe book filtering it to recipes. Available Java recipes, unlocks, crafting
grid size, search, and the craftable toggle still determine which entries can
actually appear.

The recording includes entries such as potions and a trident, which have no
vanilla crafting-table recipe in Java. Those will not appear merely to fill the
same grid positions. Matching the catalog is not a promise of identical visible
row positions when the two editions expose different recipe sets.

## Explicit limits

- Java-only additions and outputs absent from the pinned Bedrock catalog remain
  visible, using Java category membership and recipe grouping as a fallback.
  They appear after catalog entries. They are not presented as verified Bedrock
  ordering.
- Bedrock-only items without a Java mapping are omitted; the mod never invents
  recipes for them.
- Identical recipe outputs are shown once when their item, components, and
  output count agree. A currently craftable alternative recipe is preferred.
  Different components or output counts remain distinct.
- Display and ghost stacks retain their data components for server-added items.
  Recipe placement and result transfers still use Java's normal server protocol.
